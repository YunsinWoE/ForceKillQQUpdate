# QQ 更新锁

关掉 QQ 的热更新自动下载和自动升级，让 QQ 停在你现在用的这个版本。

设置里那个"自动更新"开关管不到热更新，所以关掉它照样会升级——这个工具直接掐断热更新的判断链路。

## 使用

四个文件，双击就行：

| 文件 | 作用 |
|---|---|
| `关闭更新.cmd` | 锁定到当前版本，运行时会问你选哪一层锁定 |
| `关闭更新-强兜底.cmd` | 同上，但直接选"黑名单 + 文件系统兜底"，不问 |
| `恢复更新.cmd` | 解开，恢复正常自动更新 |
| `查看状态.cmd` | 查看锁定状态（只读，不改任何东西） |

第一次运行如果权限不足会自己弹 UAC 要管理员权限。QQ 开着会提示是否关闭，同意即可。

想确认效果：启动 QQ，打开 `%APPDATA%\QQ\log\updater.log`，看到这行就说明生效了：

```
hotUpdateApi checkIsOnErrorVersion result: true
```

并且后面**不会**再出现 `DOWNLOADING`。

### 锁定层级怎么选

`关闭更新.cmd` 会把两种层级列出来让你选：

```
 [1] 仅黑名单（推荐）
     把目标版本写进 QQ 自己的 onErrorVersions，更新在下载前终止。
     versions 目录零改动，不涉及任何权限，不影响卸载/修复/安装。

 [2] 黑名单 + 文件系统兜底
     额外给 versions 目录加拒绝规则：禁止新建文件和子目录。
     连将来全新版本号的更新包都落不了盘（连流量都不走）。
     代价：卸载 / 修复 / 覆盖安装 QQ 前必须先"恢复更新"。
```

| | 仅黑名单 `[1]` | 再加兜底 `[2]` |
|---|---|---|
| 改 `config.json` 黑名单 | 有 | 有 |
| versions 目录权限 | 完全不动 | 禁止新建文件 / 子目录 |
| 已有文件写入 | 不受影响 | 不受影响 |
| 已知的新版本（如 9.9.37） | 拦住，下载都不发生 | 拦住，下载都不发生 |
| 将来全新版本 | 会先下一次包，再被黑名单拦住 | 连包都落不了盘 |
| 卸载 / 修复 / 覆盖安装 | 可直接装 | 必须先"恢复更新" |

选完会记在 `lock-state.json` 里，下次问你时把它当默认值。命令行直接指定层级：

```powershell
QQUpdateLock.ps1 -Action off -Backstop none   # 仅黑名单
QQUpdateLock.ps1 -Action off -Backstop acl    # 加文件系统兜底
```

想换层级就再跑一次 `关闭更新`：从 `[2]` 换回 `[1]` 会自动把拒绝规则撤掉、权限恢复原样。

`查看状态.cmd` 第一眼就给出结论，锁定层级直接写在标题里，不用再数别的行：

```
QQ 更新锁 · 状态

  ============================================================
    已锁定  ·  仅黑名单锁
    停在 9.9.36-53644：已知新版本在下载前就被拦下（目录写保护未开）
  ============================================================
    当前版本   : 9.9.36-53644
    拦截版本   : 9.9.37-54395
    待应用更新 : 无
    残留更新包 : 0 个 (0 MB)
    版本目录   : 9.9.36-53644
    安装目录   : C:\Program Files\Tencent\QQNT

    QQ 进程    : 未运行
```

四种状态，颜色也不同：

| 标题 | 含义 |
|---|---|
| `已锁定 · 文件强锁` | 黑名单 + 目录写保护都开着，最严 |
| `已锁定 · 仅黑名单锁` | 只有黑名单生效，目录权限没动 |
| `已锁定 · 文件强锁（但黑名单为空）` | 写保护开着但没记录要拦的版本，建议重跑一次「关闭更新」 |
| `未锁定 · QQ 会照常自动下载并升级` | 没锁 |

如果装了多份 QQ 会逐个列出来，最上面还有一行总览（几处已锁、几处强锁、几处没锁）。另外 `待应用更新` 万一出现具体版本号并标红，说明有更新已就绪、下次启动就会生效，需要重跑「关闭更新」。

## 兼容性

- **QQ 版本**：适用于 QQNT 架构的全部版本（9.9.x 及以后）。不写死任何版本号——安装位置、当前版本、要拦截的版本都是运行时自动识别的。
- **QQ 位置**：自动从注册表卸载项、正在运行的 QQ 进程、常见安装目录定位。多份 QQ 安装会逐个处理。
- **系统**：Windows 10 / 11，自带 PowerShell 5.1 即可，不需要装任何东西。
- **被拦截的版本**从四个来源自动收集：`config.json` 的 `readyVersion`、已下载的 `*.zip`、多余版本目录、以及 QQ 自己的日志（`updater.log` / `app_launcher-*.log`）。所以在一台从没跑过本工具的机器上，只要 QQ 曾经尝试过更新，它也能直接识别出目标版本。


## 常见问题

**找不到安装目录**：用 `-InstallRoot` 指到 QQ.exe 所在目录（要有 `versions` 子目录）。

**恢复更新后还是老版本**：正常，`恢复更新.cmd` 只是放开限制，实际升级要等 QQ 自己检查到新版本。

**卸载 / 修复 / 覆盖安装 QQ 前**：如果你开过 `-Backstop acl`，先跑一次 `恢复更新.cmd`，否则安装程序写不进 `versions` 目录。默认模式（不开 acl）没有这个限制。

**已知限制**：服务端下发的"最低版本强制更新"拦不住，那是服务器策略；非 QQNT 架构的老版 QQ（9.7 及以前）不适用，本工具只处理 `versions\config.json` 这套机制。

## 文件说明

| 文件 | 说明 |
|---|---|
| `关闭更新.cmd` | 双击入口，运行后选锁定层级 |
| `关闭更新-强兜底.cmd` | 双击入口，直接黑名单 + 文件系统兜底 |
| `恢复更新.cmd` | 双击入口，解开全部限制 |
| `查看状态.cmd` | 双击入口，只读查看 |
| `QQUpdateLock.ps1` | 主逻辑，可单独带参数调用 |
| `lock-state.json` | 记录锁定版本、已拦截版本、上次层级；可删（删了会重新从日志识别） |
